## 🔴 HIGH PRIORITY - Fix Before Production

### Task 1: Move Authentication Tokens to httpOnly Cookies ✅ COMPLETED
**Risk:** HIGH - Tokens in localStorage are vulnerable to XSS attacks
**Effort:** Medium (2-3 hours)
**Files:**
- `backend/app/api/auth.py` - Modify login/register/refresh endpoints
- `frontend/src/lib/stores/auth.ts` - Remove localStorage usage
- `backend/app/core/security.py` - Update get_current_user dependency

**Implementation:**
1. Backend: Modify `/login` endpoint to set httpOnly cookies instead of returning tokens in response body
2. Backend: Update `get_current_user()` to read token from cookie instead of Authorization header
3. Frontend: Update all auth API calls to include `credentials: 'include'`
4. Frontend: Remove all `localStorage.setItem/getItem('auth_token')` calls
5. Test login/logout flow with cookies

**Cookie settings:**
- `httponly=True` - Not accessible to JavaScript
- `secure=True` - HTTPS only (production)
- `samesite="strict"` - CSRF protection
- `max_age=900` - 15 minutes for access token

### Task 2: Implement Automatic Token Refresh ✅ COMPLETED
**Risk:** HIGH - Users must re-authenticate every 15 minutes
**Effort:** Medium (2-3 hours)
**Files:**
- `frontend/src/lib/api/client.ts` - Create API client with refresh logic
- `frontend/src/lib/stores/auth.ts` - Use new API client
- `backend/app/api/auth.py` - Ensure `/refresh` endpoint sets new cookie

**Implementation:**
1. Create `apiRequest()` wrapper function that handles 401 responses
2. On 401, call `/api/auth/refresh` endpoint once
3. Retry original request if refresh succeeds
4. Logout user if refresh fails
5. Prevent concurrent refresh requests with promise caching
6. Update all frontend API calls to use new wrapper

**Keep it simple:** Don't implement proactive refresh timers - only refresh on 401.

**Note:** PyJWT has very similar API - minimal changes needed.

## Notes on Simplicity

**What to AVOID:**
- ❌ Complex token rotation schemes
- ❌ Client-side JWT parsing/validation
- ❌ Premature optimization of refresh logic
- ❌ Over-engineered CSP with nonces
- ❌ Abstract factory patterns for exporters
- ❌ Comprehensive E2E test suite initially

**What to FAVOR:**
- ✅ Use existing libraries (bleach, PyJWT, python-magic)
- ✅ Server-side validation only
- ✅ Simple refresh-on-401 pattern
- ✅ Environment-based CSP configs
- ✅ Direct function calls
- ✅ Unit tests for critical paths only

**Principle:** Make it work, make it right, make it fast - in that order.
