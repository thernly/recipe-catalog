# AI Recipe Generation Feature

## Overview

Feature 18 implements AI-powered recipe generation from available ingredients using OpenRouter API. Users can input ingredients they have on hand, optionally specify constraints (cuisine type, time limit, dietary preferences, equipment), and receive a complete recipe generated by AI.

## Features

- **Ingredient-Based Generation**: Enter a list of ingredients and get a complete recipe
- **Optional Constraints**:
  - Cuisine type (e.g., Italian, Mexican, Asian)
  - Maximum cooking time
  - Dietary preferences (Vegetarian, Vegan, Gluten-Free, etc.)
  - Available kitchen equipment
- **Recipe Preview & Edit**: Review and edit the AI-generated recipe before saving
- **Food Safety Disclaimer**: Clear warnings about reviewing AI-generated recipes for safety
- **Rate Limiting**: Configured to 50 requests per hour per user
- **Source Tracking**: Recipes are marked as "ai-generated" in the system

## Setup

### 1. Get OpenRouter API Key

1. Visit [OpenRouter.ai](https://openrouter.ai/)
2. Sign up for an account
3. Navigate to your API keys section
4. Create a new API key

### 2. Configure Environment Variables

Add the following to your `backend/.env` file:

```bash
# AI / OpenRouter
OPENROUTER_API_KEY=your-api-key-here
OPENROUTER_MODEL=anthropic/claude-3.5-sonnet
AI_RATE_LIMIT_PER_HOUR=50
```

### 3. Available Models

OpenRouter supports various models. The default is `anthropic/claude-3.5-sonnet`, but you can use:
- `anthropic/claude-3.5-sonnet` (recommended for quality)
- `openai/gpt-4-turbo`
- `openai/gpt-3.5-turbo` (cheaper option)
- See [OpenRouter Models](https://openrouter.ai/models) for full list

## Usage

### For Users

1. Navigate to **✨ AI Generate** in the main navigation
2. Enter your available ingredients (one per line or comma-separated)
3. Optionally set constraints:
   - Choose a cuisine type
   - Set a maximum cooking time
   - Select dietary preferences
   - Select available equipment
4. Click **Generate Recipe**
5. Review the generated recipe
6. Edit any fields as needed
7. Click **Save Recipe** to add it to your catalog

### API Endpoint

```
POST /api/ai/generate-recipe
```

**Request Body:**
```json
{
  "ingredients": ["chicken breast", "bell peppers", "onion", "rice"],
  "cuisine": "Asian",
  "time_limit": 45,
  "dietary_preferences": ["gluten-free"],
  "equipment": ["Stovetop", "Rice cooker"]
}
```

**Response:**
```json
{
  "recipe": {
    "name": "Asian Chicken Stir-Fry with Rice",
    "description": "A quick and flavorful chicken stir-fry...",
    "recipeYield": "4 servings",
    "prepTime": "PT15M",
    "cookTime": "PT30M",
    "totalTime": "PT45M",
    "recipeIngredient": [...],
    "recipeInstructions": [...],
    "recipeCategory": ["Main Course"],
    "recipeCuisine": ["Asian"],
    "equipment": ["Stovetop", "Rice cooker"],
    "notes": "..."
  },
  "source_type": "ai-generated"
}
```

## Architecture

### Backend Components

- **`app/services/ai.py`**: Core AI service using OpenRouter API
  - Handles API communication
  - Builds prompts from user input
  - Validates and parses AI responses
  - Error handling and logging

- **`app/api/ai.py`**: FastAPI endpoints for AI features
  - Rate limiting (50 requests/hour)
  - Authentication required
  - Error handling

- **`app/schemas/ai.py`**: Pydantic schemas for request/response validation

### Frontend Components

- **`routes/ai-generate/+page.svelte`**: Main AI recipe generation page
  - Input form for ingredients and constraints
  - Recipe preview and editing
  - Food safety disclaimers

- **`lib/api/ai.ts`**: TypeScript API client for AI endpoints

### Recipe Schema

Generated recipes follow the Schema.org Recipe format with:
- `recipeIngredient`: Array of ingredient strings
- `recipeInstructions`: Array of instruction steps
- `prepTime`, `cookTime`, `totalTime`: ISO 8601 duration format (e.g., "PT30M")
- `recipeYield`: Servings (e.g., "4 servings")
- `equipment`, `notes`, `keywords`: Additional metadata

## Cost Considerations

- OpenRouter charges per token used
- Costs vary by model (Claude 3.5 Sonnet is premium, GPT-3.5 is cheaper)
- Rate limiting helps control costs (default: 50 requests/hour per user)
- Monitor usage in OpenRouter dashboard

## Security & Safety

1. **Rate Limiting**: Prevents abuse with 50 requests/hour limit
2. **Authentication Required**: Only authenticated users can generate recipes
3. **Food Safety Disclaimer**: Clear warnings displayed to users
4. **API Key Security**: Never expose API keys in frontend code
5. **Logging**: Usage is logged for monitoring (no sensitive data)

## Troubleshooting

### "OPENROUTER_API_KEY not configured"
- Ensure the API key is set in `backend/.env`
- Restart the backend server after adding the key

### "Rate limit exceeded"
- User has exceeded 50 requests in the last hour
- Wait for the rate limit window to reset
- Adjust `AI_RATE_LIMIT_PER_HOUR` in config if needed

### "AI service error"
- Check OpenRouter API status
- Verify API key is valid
- Check backend logs for detailed error messages
- Ensure you have credits in your OpenRouter account

### Poor recipe quality
- Try a different model (e.g., upgrade to GPT-4)
- Provide more specific constraints
- Add more detailed ingredients
- Edit the generated recipe before saving
